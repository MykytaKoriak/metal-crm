# MKCRM

MKCRM — это Django CRM/ERP-система для работы с клиентами, заказами, задачами и производственным контуром. Проект объединяет:

- CRM-базу клиентов и контактов
- каталог продуктов
- заказы с позициями, оплатой и доставкой
- задачи с workflow и kanban-доской
- производственные этапы, слоты, календарь и планировщик
- отчеты по загрузке, свободным окнам, просроченным этапам и заказам в работе
- Telegram-бота для команд и уведомлений
- ролевую модель доступа и аудит изменений

Проект ориентирован на внутреннюю эксплуатацию командой продаж, производства и руководством.

## 1. Что умеет система

### 1.1 CRM-контур

- Вести базу клиентов с типом клиента, телефоном, email, источником и тегами.
- Хранить несколько контактов на одного клиента.
- Вести каталог продуктов с SKU, базовой ценой, описанием и ссылками на внешние площадки.
- Создавать и редактировать заказы с позициями, сроком, доставкой, оплатой и комментарием.
- Автоматически формировать название заказа по позициям.
- Назначать менеджера и приоритет заказа.
- Отслеживать статусы заказа:
  - `Новый`
  - `В работе`
  - `В производстве`
  - `Готов`
  - `Завершён`
  - `Отменён`

### 1.2 Задачи

- Создавать задачи, связанные с клиентом, контактом и заказом.
- Назначать постановщика и исполнителя.
- Работать со статусами задач:
  - `Новая`
  - `В работе`
  - `Ожидает`
  - `Выполнено`
- Использовать отдельный список задач с фильтрами.
- Использовать kanban-доску задач с быстрым изменением статуса.
- Видеть задачи в личном кабинете и на sales dashboard.

### 1.3 Производство

- Автоматически создавать производственные этапы для позиций заказа.
- Автоматически строить `ProductionSlot` для этапов.
- Перепланировать открытые заказы при изменении приоритета, сроков и ресурсов.
- Вести производственные ресурсы:
  - станки `Machine`
  - участки `WorkUnit`
- Учитывать:
  - активность ресурса
  - рабочие дни
  - рабочие часы
  - простои и блокировки `ResourceDowntime`
- Жестко валидировать production calendar:
  - без пересечений слотов на одном ресурсе
  - без выхода за рабочее время
  - без попадания в downtime
  - с учетом порядка этапов
- Работать в отдельном production workspace:
  - очередь этапов
  - календарь слотов
  - быстрые действия `Start / Done / Block / Cancel`
  - перегруженные ресурсы
  - свободные окна
  - просроченные этапы

### 1.4 Отчеты

- Отчет по загрузке станков и участков.
- Детальные отчеты по каждому станку и участку.
- Отчет по свободным слотам.
- Отчет по просроченным этапам.
- Отчет по заказам в работе.
- Производственный календарь слотов.

### 1.5 Дашборды

- `Administrator dashboard`
  - пользователи, роли, общая статистика и выручка
- `Sales dashboard`
  - мои задачи, ближайшие дедлайны, статусы заказов
- `Production dashboard`
  - очередь этапов, просрочки, загрузка, свободные окна, быстрые действия
- `Executive dashboard`
  - проблемные зоны, заказы с риском, критичные ресурсы, зависшие задачи, доля заказов в производстве, конверсия по статусам

### 1.6 Telegram

- Привязка Telegram-чата к аккаунту через код из CRM.
- Команды:
  - `/start`
  - `/link CODE`
  - `/unlink`
  - `/tasks`
  - `/orders`
- Inline-навигация по задачам и заказам.
- Уведомления:
  - новая задача
  - дедлайн задач
  - просрочка задач
  - смена статуса заказа
  - дедлайн заказа
  - просрочка заказа
  - ключевые события производства

### 1.7 Контроль доступа и аудит

- Роли:
  - `Administrator`
  - `Sales manager`
  - `Production / Technologist`
  - `Executive`
- Row-level visibility для order/task/stage/slot-зависимых данных.
- Аудит изменений для:
  - заказов
  - задач
  - производственных этапов
  - производственных слотов
- В журнале аудита сохраняются:
  - действие
  - кто изменил
  - какие поля изменены
  - состояние `before`
  - состояние `after`
  - дата изменения

## 5. Переменные окружения

Минимально проект ожидает переменные базы и суперпользователя.

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `POSTGRES_DB` | да для Docker/PostgreSQL | `django_db` | имя БД |
| `POSTGRES_USER` | да для Docker/PostgreSQL | `django_user` | пользователь БД |
| `POSTGRES_PASSWORD` | да для Docker/PostgreSQL | `django_password` | пароль БД |
| `POSTGRES_HOST` | да для локального PostgreSQL | `db` | хост БД |
| `POSTGRES_PORT` | нет | `5432` | порт БД |
| `DJANGO_SUPERUSER_USERNAME` | желательно | нет | логин суперпользователя для `createsu` |
| `DJANGO_SUPERUSER_EMAIL` | нет | пусто | email суперпользователя |
| `DJANGO_SUPERUSER_PASSWORD` | желательно | нет | пароль суперпользователя |
| `APP_BASE_URL` | желательно | пусто | базовый URL для ссылок из Telegram |
| `TELEGRAM_BOT_TOKEN` | нужен только для Telegram | пусто | токен бота |
| `TELEGRAM_WEBHOOK_SECRET` | нет | пусто | секрет webhook |

Пример `.env`:

```env
POSTGRES_DB=django_db
POSTGRES_USER=django_user
POSTGRES_PASSWORD=django_password
POSTGRES_HOST=db
POSTGRES_PORT=5432

DJANGO_SUPERUSER_USERNAME=admin
DJANGO_SUPERUSER_EMAIL=admin@example.com
DJANGO_SUPERUSER_PASSWORD=admin123

APP_BASE_URL=http://localhost:8000
TELEGRAM_BOT_TOKEN=
TELEGRAM_WEBHOOK_SECRET=
```

## 7. Быстрый старт через Docker

### 7.1 Полный запуск с Telegram

1. Создайте файл `.env` в корне проекта.
2. Заполните переменные БД, суперпользователя и `TELEGRAM_BOT_TOKEN`.
3. Запустите:

```bash
docker compose up --build
```

Что делает `web` сервис на старте:

1. `makemigrations crm`
2. `makemigrations manufacture`
3. `migrate`
4. `createsu`
5. `collectstatic --noinput`
6. `seed_demo_data`
7. `runserver 0.0.0.0:8000`

Что делает `telegram` сервис:

- запускает бесконечный polling loop командой `run_telegram_bot`
- забирает входящие updates
- отправляет очереди уведомлений и напоминаний

После старта:

- CRM будет доступна на `http://localhost:8000`
- БД PostgreSQL будет доступна на `localhost:5432`

### 7.2 Запуск без Telegram

Если Telegram пока не нужен, не запускайте сервис `telegram` без токена. Используйте:

```bash
docker compose up --build db web
```

Или удалите/закомментируйте сервис `telegram` в `docker-compose.yml`.

### 7.3 Полезные Docker-команды

Проверить логи приложения:

```bash
docker compose logs -f web
```

Проверить логи Telegram-сервиса:

```bash
docker compose logs -f telegram
```

Запустить роль-аккаунты вручную:

```bash
docker compose exec web python manage.py create_role_accounts --password ChangeMe123!
```

Открыть shell:

```bash
docker compose exec web python manage.py shell
```

## 10. Системные аккаунты и роли

Команда `create_role_accounts` создает по одному аккаунту на роль:

| Роль | Email/username |
|---|---|
| Administrator | `admin@mkcrm.local` |
| Sales manager | `sales.manager@mkcrm.local` |
| Production / Technologist | `production@mkcrm.local` |
| Executive | `executive@mkcrm.local` |

Пароль задается аргументом `--password`.

Важно:

- superuser из `createsu` и role accounts — это разные механизмы
- `seed_demo_data` не создает удобные логины для всех ролей
- для полноценной проверки интерфейсов по ролям используйте `create_role_accounts`

## 11. Правила доступа

### 11.1 Page-level доступ

- `Administrator` — полный доступ.
- `Sales manager` — CRM CRUD + просмотр производственного контура.
- `Production / Technologist` — CRUD по производству + read-only CRM.
- `Executive` — read-only доступ.

### 11.2 Data-level доступ

- менеджер видит только свои заказы и связанные задачи
- production видит производственный контур
- executive и admin видят весь массив данных
- row-level фильтрация подключена к спискам, карточкам, отчетам, API и admin querysets

## 12. Подробная инструкция по использованию CRM

### 12.1 Вход в систему

1. Откройте `/accounts/login/`.
2. Введите email или username и пароль.
3. После входа `/dashboard/` автоматически перенаправит вас на dashboard вашей роли.

### 12.2 Работа менеджера

#### Клиенты

Раздел: `/crm/clients/`

Что можно делать:

- смотреть список клиентов
- искать по имени, телефону, email, коду
- открывать карточку клиента
- создавать клиента
- редактировать клиента
- удалять клиента, если это не блокируется связями

В карточке клиента доступно:

- основная информация
- список контактов
- список заказов
- список задач
- быстрые действия:
  - добавить контакт
  - создать заказ
  - создать задачу

#### Контакты

Раздел: `/crm/contacts/`

Что можно делать:

- вести контактных лиц клиента
- хранить должность, телефон, email, источник и теги
- создавать контакт из карточки клиента
- редактировать и удалять контакт

#### Продукты

Раздел: `/crm/products/`

Что можно делать:

- вести каталог продукции
- хранить SKU, цену, описание и техническое описание
- хранить ссылки на внешний сайт, маркетплейсы, фото и нормы
- использовать продукт в позициях заказа

#### Заказы

Раздел: `/crm/orders/`

Что можно делать:

- создавать заказ
- выбирать контакт и менеджера
- задавать приоритет
- задавать дедлайн
- добавлять позиции заказа
- указывать способ доставки
- хранить получателя, телефон получателя и ТТН
- хранить тип оплаты, условия оплаты и сумму
- редактировать заказ
- удалять заказ

Что происходит автоматически:

- название заказа собирается по позициям
- для позиций создаются производственные этапы
- planner пытается построить слоты производства
- статус заказа синхронизируется с состоянием производства

#### Задачи

Разделы:

- `/crm/tasks/`
- `/crm/tasks/kanban/`

Что можно делать:

- создавать задачу на клиента, контакт или заказ
- назначать исполнителя
- менять статус
- фильтровать по исполнителю, клиенту, заказу, дедлайну и статусу
- работать через kanban-доску
- быстро менять статус карточки

Workflow задач:

1. `Новая`
2. `В работе`
3. `Ожидает`
4. `Выполнено`

### 12.3 Работа производства

Основной раздел: `/dashboard/production/`

Экран включает:

- очередь производственных этапов
- календарь слотов

- перегруженные ресурсы

- `Новый`

Быстрые действия:

Ресурсы:

Каждый ресурс может иметь:

## 13. Производственный контур подробно

### 13.1 Этапы

Для каждой позиции заказа система создает этапы:

1. `Приемка`
2. `Закупка материалов`
3. `Выполнение`
4. `Покраска`
5. `Готово к отправке`

### 13.2 Слоты

`ProductionSlot` — это плановая единица календаря производства.

Слот хранит:

- заказ
- этап
- тип слота
- тип операции
- ресурс
- время начала и окончания
- источник планирования
- режим `auto/manual`
- признак фиксации
- назначение
- комментарий диспетчера
- служебный комментарий

### 13.3 Planner

Planner:

- строит слоты автоматически
- учитывает последовательность этапов
- учитывает дедлайны и приоритет
- учитывает рабочие часы и доступность ресурсов
- учитывает занятость и downtime
- сохраняет ручные слоты как зафиксированные

### 13.4 Отчеты производства

Доступные отчеты:

- `/report/machine-load/` — загрузка ресурсов
- `/report/free-slots/` — свободные окна
- `/report/orders-in-work/` — незавершенные заказы с текущим этапом и рисками
- `/report/overdue-stages/` — просроченные или зависшие этапы

## 14. Telegram: настройка и использование

### 14.1 Что нужно для запуска

В `.env` задайте:

```env
TELEGRAM_BOT_TOKEN=ваш_токен
APP_BASE_URL=http://localhost:8000
TELEGRAM_WEBHOOK_SECRET=optional_secret
```

### 14.2 Привязка аккаунта

1. Войдите в CRM.
2. Откройте `/account/me/`.
3. Скопируйте код привязки Telegram.
4. Напишите боту:

```text
/link ВАШ_КОД
```

После привязки доступны:

```text
/start
/tasks
/orders
/unlink
```

### 14.3 Как работает интеграция

Через Docker:

- сервис `telegram` постоянно крутит polling loop
- входящие команды обрабатываются автоматически
- очередь уведомлений отправляется автоматически

Без Docker:

- запускайте `run_telegram_bot`
- либо используйте webhook и отдельно запускайте отправку уведомлений

### 14.4 Webhook-режим

Если нужен webhook вместо polling:

- поднимите доступный извне URL
- задайте `APP_BASE_URL`
- используйте endpoint `/integrations/telegram/webhook/`
- при необходимости задайте `TELEGRAM_WEBHOOK_SECRET`

## 15. Аудит изменений

Журнал аудита фиксирует изменения по:

- заказам
- задачам

Что хранится:

- тип сущности
- действие
- кто изменил

## 19. Частые вопросы и замечания

### Проект не стартует через `docker compose up`

Проверьте:

- заполнен ли `.env`
- задан ли `DJANGO_SUPERUSER_USERNAME`
- задан ли `DJANGO_SUPERUSER_PASSWORD`
- задан ли `TELEGRAM_BOT_TOKEN`, если запускается сервис `telegram`

Если Telegram пока не нужен:

```bash
docker compose up --build db web
```

### Не создаются role accounts

Они не создаются автоматически при `docker compose up`. Выполните вручную:

```bash
docker compose exec web python manage.py create_role_accounts --password ChangeMe123!
```

### Telegram не отвечает

Проверьте:

- есть ли `TELEGRAM_BOT_TOKEN`
- запущен ли сервис `telegram`
- есть ли привязка чата в `/account/me/`
- смотрите логи:

```bash
docker compose logs -f telegram
```

### Почему superuser не равен role account

Superuser создается командой `createsu` из `.env`. Role accounts создаются отдельно и нужны для проверки ролевых интерфейсов.

## 20. Важные ограничения текущей конфигурации

- `docker-compose.yml` запускает `makemigrations` на каждом старте контейнера.
- Запуск идет через Django `runserver`, то есть это dev-ориентированная конфигурация.
- `ALLOWED_HOSTS` в текущих settings ограничен и для публичного продакшена потребует настройки.
- Для production-развертывания стоит вынести init-команды в отдельный bootstrap шаг и заменить `runserver` на WSGI/ASGI-сервер.
